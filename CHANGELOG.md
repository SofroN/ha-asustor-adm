## [0.2.0] - 2026-11-16

### Добавлено

- Выпуск по версии: когда в `main` попадает `VERSION` с большим номером, workflow `Release` сам ставит тег `vX.Y.Z` и публикует релиз. Повторный пуш и понижение версии релиза не создают, а ручной запуск остаётся для bump номера из интерфейса Actions.
- К релизу прикладывается архив `asustor_adm-X.Y.Z.zip` с каталогом `custom_components/asustor_adm/` внутри — распаковка в корень конфигурации Home Assistant (`unzip asustor_adm-X.Y.Z.zip -d /config`) даёт готовый плагин без HACS.
- Текст релиза описывает изменения относительно прошлого релиза: раздел `CHANGELOG.md` выпускаемой версии, коммиты с прошлого тега, сгруппированные по Conventional Commits, и ссылка сравнения. Если раздел CHANGELOG не заполнен, релиз всё равно выходит со списком коммитов.
- Иконки интеграции — фирменный знак ASUSTOR в `brand/`: квадратная иконка-знак и горизонтальные логотипы для светлой и тёмной темы в 1x и 2x. Источник — каталог `dashboard-icons`, отдельный тёмный вариант иконки не нужен: знак несёт собственный фон.
- Явные иконки сущностей там, где `device_class` не различает смысл: утилизация памяти, тома и внешнего диска, приём и передача сети, чтение и запись диска, кнопки питания. Сущности с точным классом устройства иконку не переопределяют, правило проверяет `tests/test_icons.py`.
- Перенастройка существующей записи: адрес, порт, режим TLS и учётные данные меняются через меню записи, без удаления устройства и его сущностей. Проверка подключения должна вернуть тот же NAS; отказ получает причину «по этому адресу отвечает другой NAS».

### Изменено

- Релиз собирается атомарно: черновик, загрузка архива, публикация. Пока архив не загружен, релиз остаётся черновиком и не виден пользователям; повторный запуск дозагружает недостающее и публикует его.
- Сущность обновления ADM создаётся только при подтверждённой целевой версии, которая строго новее установленной. На ADM 5.1.4, где NAS не сообщает целевую версию, сенсор обновления остаётся «недоступно».

### Исправлено

- Ложное «доступно обновление ADM», когда обновления нет: признак теперь выводится из сверки установленной и целевой версий по сегментам, а не из флага уведомления ADM, который остаётся включённым и при последней версии ПО. Флаг уведомления и время последней проверки публикуются как атрибуты сенсора и в разделе `firmware` выгрузки диагностики.
- Службы SMB, NFS, FTP, WebDAV и SNMP снова публикуют состояние: ADM отдаёт их настройки только вместе с параметром `tab` (`cifs`, `Nfs_Get_Enable`, `general`, `webdav`, `Get`), без него отвечал кодом 5302 и признаки оставались недоступными. Проверено на живом ADM 5.1.4.DM62.
- Число активных сессий снова публикуется: список сессий ADM отдаёт только вместе с параметрами постраничности (`sort`, `ascend`, `start`, `limit`), без них отвечал кодом 5302.
- Учётная запись с двухфакторной авторизацией получает ошибку «требуется одноразовый код» вместо «неверные учётные данные»: ADM сообщает об этом кодом 5034, а клиент передаёт признак `two-step-auth`, как интерфейс ADM.
- Коды проверки обновлений приведены к подтверждённым значениям: `6209` — установлена последняя версия, `6215` — та же версия, `5005` — нет связи с сервером обновлений; коды контекстны для каждого CGI.
- Недостаток прав учётной записи ADM распознаётся отдельно: вместо «непредвиденной ошибки» настройка сообщает «недостаточно прав» и подсказывает про группу администраторов. Тело отказа по правам неотличимо от тела истёкшей сессии, поэтому причина подтверждается флагом `isadministrators` из ответа авторизации.
- Английский интерфейс снова на английском: `strings.json` и `translations/en.json` содержали русские строки настройки, перенастройки, переавторизации, ошибок и интервалов опроса, поэтому при языке `en` эти диалоги выходили на русском. Русский текст остался только в `translations/ru.json`; тест `test_english_source_has_no_russian_text` не даёт вернуть кириллицу в исходник строк.

## [0.1.0] - 2026-11-15

### Добавлено

- Интеграция ASUSTOR NAS (ADM) как пользовательский репозиторий HACS: домен `asustor_adm`, настройка через интерфейс, переавторизация при смене пароля.
- Клиент внутреннего HTTP API ADM на порту 8001: form-urlencoded POST, `sid` в query, разбор конверта ответа, одна повторная авторизация по коду `5000`.
- Системные метрики: загрузка процессора, памяти и томов, температура, обороты кулеров, сеть и пользователи онлайн.
- Состояние хранилищ: тома, диски и их SMART, состояние RAID, внешние диски.
- Статус сервисов и приложений ADM, включая активность и задания.
- Обновления прошивки ADM: установленная и доступная версии, сущность обновления.
- Управление питанием: выключение, перезагрузка и сон — только при подтверждённых правах администратора.
- Диагностика с маскированием пароля, `sid`, учётной записи, серийного номера и адресов.
- Переводы интерфейса на английский и русский языки.

### Изменено

- CI ведётся одним файлом `.github/workflows/ci.yml` для GitHub Actions и Forgejo Actions; метка раннера берётся из переменной `CI_RUNNER`.
