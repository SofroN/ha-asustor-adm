# Design

## Context

См. `proposal.md` — Why. Здесь только развилки и их основания.

Наблюдения, определившие решения:

- Исходное состояние: `brand/icon.png` — 256×256, ровно один цвет `#2196f3` на 65536 пикселей; `brand/icon@2x.png` — 512×512, тот же единственный цвет. Оба файла — RGB без альфа-канала, то есть непрозрачный квадрат-заливка.
- Официальный сайт производителя: `https://www.asustor.com/images/ASUSTOR_Logo_SVG_white.svg` (180×48, `viewBox="0 0 180 48"`, полезный контур — 152.855×28, все заливки `#fff`). Сайт отвечает `403` на запросы без браузерного `User-Agent`, с ним — `200`.
- Другие официальные варианты искались и не найдены: `ASUSTOR_Logo_SVG.svg`, `_black`, `_color`, `/images/logo.svg`, `/images/logo.png` — `404`; `favicon.ico` — 16×16 (для иконки 256 px бесполезен); веб-манифест, `apple-touch-icon`, `browserconfig.xml` — `404`; страницы `/en/press`, `/en/brand`, `/en/media_kit` — `404`, пресс-кита с вектором нет.
- Внешние каталоги: на Wikimedia Commons логотипа ASUSTOR нет (поиск по файлам даёт только фотографии устройств), в `home-assistant/brands` записи `custom_integrations/asustor_adm` нет.
- Тёмный вариант на сайте — тот же контур: на официальном социальном изображении `asustor_social.png` логотип чёрный, доминирующие тёмные кластеры `#000000`–`#101010`.

## Goals / Non-Goals

**Goals:**

- В интерфейсе Home Assistant и в HACS вместо цветной заглушки — узнаваемый официальный логотип.
- Набор файлов соответствует ожиданиям Home Assistant: 1x и 2x, светлая и тёмная темы, квадратная иконка и горизонтальный логотип.
- Замена отслеживается тестом, чтобы заглушка не вернулась и чтобы файлы не разъехались по размерам.

**Non-Goals:**

- Изменение кода платформ, состава сущностей и поведения интеграции.
- Собственная графика «в стиле бренда»: рисуем только то, что есть у производителя.
- Зависимость сборки или CI от растеризатора SVG.

## Decisions

### D1. Источник — только официальный сайт производителя

Альтернативы и причины отказа:

| Источник | Итог |
| --- | --- |
| Официальный SVG с asustor.com | взят: единственный вектор бренда, отдан самим правообладателем |
| Wikimedia Commons | логотипа нет, только фотографии устройств |
| `home-assistant/brands` | записи для `asustor_adm` нет |
| `favicon.ico` сайта | 16×16, не масштабируется до 256 px |
| Пресс-кит `/en/press`, `/en/brand`, `/en/media_kit` | `404`, вектора нет |

Файл скачивается с браузерным `User-Agent` (иначе `403`), результат фиксируется в репозитории как артефакт: сборка ничего не загружает из сети.

### D2. Квадратная иконка — официальный wordmark по центру прозрачного квадрата

У ASUSTOR нет официальной квадратной монограммы (проверено в D1), а рисовать свою — значит выдавать вымысел за бренд. Поэтому `icon.png`/`icon@2x.png` — тот же wordmark, вписанный в квадрат шириной 94 % стороны: 4 % полей хватает, чтобы логотип не прилипал к скруглению карточки, и при этом в мелком размере он читается лучше, чем при 90 %.

Отвергнуто: плашка (скруглённый квадрат с фоном) — достоверного фирменного цвета сайт не даёт, а Home Assistant ожидает от иконки прозрачный фон, чтобы она работала и на светлой, и на тёмной карточке.

### D3. Светлая тема — чёрный контур, тёмная — белый

Официальный файл белый (для тёмных страниц сайта). Для светлой темы контур перекрашивается в `#000000` — это тот же вектор, инверсия цвета, а не новая графика; на сайте логотип в светлых местах именно чёрный.

Перекраска выполняется переносом альфа-канала на сплошной цвет, а не заливкой «поверх»: сглаживание остаётся в альфе, поэтому края букв не превращаются в ступеньки.

### D4. Растеризация — разовая операция вне проекта

В системе нет `rsvg-convert`, `inkscape` и ImageMagick, а Pillow не читает SVG. Использован `cairosvg` 2.9.1, установленный во временный каталог (`pip install --target /tmp/svgpy cairosvg`, системный `libcairo` уже есть); окружение Home Assistant не менялось — Pillow в окружении остался 12.3.0, как требует установленный Home Assistant 2026.10.4.

В репозиторий попадают только готовые PNG: зависимость от растеризатора не появляется ни в интеграции, ни в CI. Размеры: иконки 256 и 512, логотипы 300 и 600 по ширине (пропорция 5.44:1).

### D5. Тест читает PNG стандартной библиотекой

Быстрый набор (`tests/unit`) не ставит Pillow, поэтому в `tests/unit/test_brand.py` компактный декодер PNG на `zlib` + `struct` с поддержкой всех пяти фильтров. Проверяются четыре свойства, которых не было у заглушки:

1. размеры: иконки строго квадратные 256/512, `logo@2x` ровно вдвое больше `logo`;
2. прозрачный фон: углы полностью прозрачны, непрозрачных пикселей 3–25 % площади;
3. центровка: поля слева/справа и сверху/снизу симметричны с допуском 2 px;
4. контраст: средняя яркость `icon@2x` ниже 40, `dark_icon@2x` выше 215 (то же для логотипов).

Проверено обратное: при подстановке прежней заливки падают три теста из четырёх (размерный — из-за RGB без альфы, фон и центровка — из-за непрозрачного квадрата).

### D6. Правовой статус файлов

Логотип ASUSTOR — товарный знак правообладателя; файлы взяты с официального сайта и используются исключительно для идентификации устройства в интерфейсе Home Assistant. Свободной лицензии на них нет и не подразумевается; при требовании правообладателя файлы удаляются, а интеграция остаётся работоспособной (brand-ассеты ни на что в коде не влияют).
