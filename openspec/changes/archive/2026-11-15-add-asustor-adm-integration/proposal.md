# Proposal

## Why

Для NAS ASUSTOR (ADM) нет ни официальной интеграции Home Assistant, ни записи в HACS default; три существующих сторонних проекта работают только через SNMP, требуют ручного включения SNMPv3 и дают лишь чтение. Внутренний HTTP API ADM (порт 8001) способен больше: он отдаёт состояние сервисов, историю SMART, доступность обновления ADM и позволяет выключать и перезагружать NAS — то есть закрывает задачи, недоступные через SNMP.

Контракт API неизвестен публично (на developer.asustor.com только упаковка приложений), поэтому перед планированием проведён спайк на реальном устройстве (AS3304T, ADM 5.1.4.RM62): 65 захваченных вызовов, схемы ответов и найденные в JS эндпоинты питания. Этого достаточно, чтобы зафиксировать поведение и начать реализацию.

## What Changes

- Новая HACS custom integration `asustor_adm` (репозиторий `ha-asustor-adm`), написанная по стандартам HA core: `ConfigFlow`, `DataUpdateCoordinator`, `Diagnostics`, `entity_registry_enabled_default` для неподтверждённых метрик.
- Клиент ADM HTTP API: form-urlencoded POST на `/portal/apis/<module>/<name>.cgi`, авторизация парой `account`/`password` → `sid` в query, обязательное пустое тело (`data=b""`), разбор конверта `success` / `error_code` с отдельной обработкой кода `5000` как истёкшей сессии.
- Два независимых цикла опроса: «быстрый» (60 с) и «медленный» (300 с), с общим клиентом и одной сессией.
- Сущности: `sensor` (ресурсы, тома, диски, диагностика), `binary_sensor` (здоровье RAID/дисков, доступность обновления ADM, статусы 8 сервисов, внешние диски), `button` (выключение, перезагрузка), `update` (ADM).
- Гейтирование сущностей по фактическим возможностям устройства и модели, чтобы на других конфигурациях не появлялись пустые датчики.
- Маскирование `password`, `sid`, `passport` в diagnostics и запрет логирования query string.

Вне скоупа этого изменения:

- UPS — API `extups.cgi` отдаёт только конфигурацию, без заряда и состояния «на батарее»; для поддержки нужен отдельный спайк.
- Переключение сервисов (только чтение статусов), управление шарами, iSCSI, установка приложений App Central.
- Гарантированная совместимость с ADM 4.x — проверка проведена только на ADM 5.1.4.
- Ветка двухфакторной авторизации: параметр `two-step-auth` в API присутствует, но на тестовом аккаунте 2FA не включена, поведение сервера не подтверждено.

## Capabilities

### New Capabilities

- `system-metrics`: жизненный цикл подключения к ADM (настройка, авторизация, восстановление сессии, разбиение опроса на быстрый и медленный циклы) и метрики самого NAS — загрузка CPU по ядрам, load average, память, температура, кулеры, uptime, сетевой обмен.
- `storage-health`: состояние томов и RAID, ёмкости и заполнение, температура и здоровье дисков, атрибуты SMART.
- `services-status`: статусы включения сетевых сервисов NAS (SMB/CIFS, NFS, FTP, WebDAV, SSH/SFTP, rsync, SNMP, TFTP) и число активных сессий.
- `firmware-updates`: установленная версия ADM, доступность обновления, счётчик доступных обновлений приложений App Central.
- `power-control`: выключение и перезагрузка NAS командами Home Assistant с учётом возможностей устройства.
- `external-devices`: внешние USB-диски — наличие, готовность, ёмкость и свободное место.

### Modified Capabilities

Нет: в проекте пока нет спецификаций.

## Impact

- Новый код: `custom_components/asustor_adm/` (клиент API, координаторы, платформы `sensor`/`binary_sensor`/`button`/`update`, `config_flow`, `diagnostics`, переводы), а также `hacs.json`, `manifest.json`, тесты.
- Зависимости: только `aiohttp` из окружения HA; сторонние PyPI-пакеты не требуются, PyPI-библиотеки для ADM API не существует.
- Home Assistant: домен `asustor_adm`, `iot_class: local_polling`, `integration_type: device`.
- Внешняя зависимость: документированного контракта ADM API нет, поэтому любое обновление прошивки ADM может изменить поля ответов. Требуется устойчивый разбор (отсутствующие поля не должны ломать координатор).
- Сетевое воздействие: 4 запроса за быстрый цикл; опрос может препятствовать засыпанию дисков, поэтому интервалы настраиваемые.
