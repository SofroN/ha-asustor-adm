# Design

## Context

Мотивация — в `proposal.md`. Текущие ассеты получены из официального вектора `ASUSTOR_Logo_SVG_white.svg`: wordmark, вписанный в прозрачный квадрат (иконка) и вытянутый в 300×55 (логотип). В `home-assistant/brands` записи нет, локальные brand-ассеты кастомной интеграции Home Assistant отдаёт с версии 2026.3.

Исходный SVG из `dashboard-icons`: `viewBox="0 0 1024 1024"`, `<circle cx="512" cy="512" r="512" fill="#0052a4"/>` и один `<path fill="#fff"/>` — wordmark. Ничего, кроме этих двух элементов, в файле нет, поэтому знак и логотип выводятся из одного источника без дорисовок.

## Goals / Non-Goals

**Goals:**

- Узнаваемая квадратная иконка в списке интеграций, диалоге добавления и на карточке устройства.
- Логотип остаётся горизонтальным и тематическим (чёрный/белый), как ожидает Home Assistant на странице интеграции.
- Ассеты проверяются тестом, чтобы знак не подменился заглушкой и файлы не разъехались по размерам.

**Non-Goals:**

- Изменение кода интеграции, сущностей и спек.
- Собственная графика или перекраска фирменного знака.
- Сборка, требующая растеризатора SVG в окружении проекта.

## Decisions

### D1. Источник — `dashboard-icons`, знак берётся как есть

Альтернативы: официальный вектор с asustor.com (только wordmark, квадратного знака у производителя нет — проверялось при добавлении ассетов), самостоятельная композиция знака (это уже не бренд, а вымысел), заявка в `home-assistant/brands` (нужны те же картинки, но появляются только после модерации).

Взят готовый знак из каталога `homarr-labs/dashboard-icons` — тот же товарный знак ASUSTOR в фирменном синем `#0052a4`. Права на знак принадлежат ASUSTOR; файлы используются только для идентификации устройства в интерфейсе Home Assistant, как и прежние ассеты. Происхождение фиксируется в `design.md` и `CHANGELOG.md`.

### D2. Иконка — круг на прозрачном квадрате, без тёмного варианта

Круг не доходит до углов, поэтому `icon.png` остаётся PNG с прозрачными углами — так Home Assistant кладёт его на любой фон карточки и не появляется светлая рамка вокруг знака. Заливка круга — собственная, поэтому тёмная тема не требует отдельного файла: `brand/dark_icon.png` удалён, а встроенная цепочка подстановок Home Assistant (`dark_icon.png → icon.png`, `IMAGE_FALLBACKS` в `components/brands/const.py`) отдаёт обычную иконку.

Альтернатива — квадратная плашка во весь файл — отклонена: на светлой карточке она даёт лишнюю синюю рамку по краям, а HA сам скругляет иконки.

### D3. Логотип — wordmark из того же SVG, чёрный и белый

Знак без круга: `<path>` из SVG на прозрачном фоне, пропорция контента 5,443, что при ширине 300 даёт ровно 55 px — прежние размеры и парность 1x/2x сохраняются, тест размеров не меняется. Для светлой темы контур чёрный, для тёмной — белый: прежняя логика контраста сохраняется, хотя источник теперь другой.

### D4. Растеризация — разовая операция вне проекта

`rsvg-convert`, `inkscape`, ImageMagick и Pillow-SVG в системе нет. Использован `cairosvg` 2.9.1, установленный во временный каталог `/tmp/svgpy`; в `requirements_test.txt` и `manifest.json` ничего не добавлено. Иконки рендерятся сразу в нужный размер (256 и 512), логотипы — из мастер-рендера 2400 px с обрезкой по непрозрачным пикселям и уменьшением до 600 и 300 px (LANCZOS), чтобы сглаживание не зависело от размера.

### D5. Тест проверяет знак, а не прежнюю форму

Прежние правила («непрозрачных 3–25 %», «светлая иконка тёмная, тёмная светлая») описывали wordmark на прозрачном фоне и для круга неверны. Новые правила: углы прозрачны, непрозрачных 60–90 % (круг занимает 78,5 %), среди непрозрачных пикселей больше 85 % заливки `#0052a4` и 2–10 % белых букв, центровка сохраняется. Контраст светлого и тёмного вариантов проверяется только для логотипов.

## Risks / Trade-offs

- **Знак из стороннего каталога, а не с сайта производителя** → это тот же товарный знак ASUSTOR; происхождение зафиксировано, файлы заменяемы одной командой, на работу интеграции не влияют.
- **Заполненная иконка выглядит иначе, чем прозрачный wordmark** → это осознанная смена оформления; на тёмной и светлой карточке знак читается одинаково за счёт собственного фона.
- **Удаление `dark_icon*.png`** → Home Assistant подставляет `icon.png` по встроенной цепочке; проверено по `IMAGE_FALLBACKS` установленной версии.
- **Растеризация воспроизводится только с `cairosvg`** → ассеты лежат в репозитории как артефакты, сборка и CI растеризатор не требуют; при повторной замене шаги описаны в `tasks.md`.

## Migration Plan

Данных для миграции нет: Home Assistant читает файлы из `custom_components/asustor_adm/brand/` при запросе картинки. После обновления интеграции иконка меняется сразу, кэш браузера может показать старую — помогает перезапуск HA и жёсткое обновление страницы. Откат — возврат прежних PNG из истории.
