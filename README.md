# ASUSTOR NAS (ADM) для Home Assistant

Интеграция Home Assistant для NAS ASUSTOR под управлением ADM: мониторинг
ресурсов, здоровье дисков и RAID, состояния сетевых сервисов, обновления ADM и
управление питанием. Работает через внутренний HTTP API ADM, без SNMP и без
облака ASUSTOR. Домен `asustor_adm`, репозиторий `ha-asustor-adm`.

## Требования

- NAS ASUSTOR с ADM 5.x (проверено на AS3304T, ADM 5.1.4.RM62) и включённой
  службой ADM на порту 8001.
- Home Assistant 2025.1 или новее.
- Учётная запись ADM из группы администраторов: на проверенной прошивке только
  она получает доступ к чтению, иначе настройка завершается ошибкой
  «недостаточно прав». Кнопки питания требуют тех же прав.

## Установка через HACS

1. HACS → Интеграции → меню → «Пользовательские репозитории».
2. Добавить `https://github.com/SofroN/ha-asustor-adm`, категория «Integration».
3. Установить интеграцию и перезапустить Home Assistant.
4. Настройки → Устройства и службы → «Добавить интеграцию» → «ASUSTOR NAS (ADM)».

## Настройка

| Поле | По умолчанию | Комментарий |
|---|---|---|
| Адрес | — | имя хоста или IP-адрес NAS |
| Порт | 8001 | порт службы ADM |
| Использовать HTTPS | включено | штатный режим ADM |
| Проверять TLS-сертификат | включено | отключите для самоподписанного сертификата |
| Учётная запись | — | имя пользователя ADM |
| Пароль | — | пароль ADM |

ADM по умолчанию использует самоподписанный сертификат: отключите проверку TLS —
соединение останется шифрованным. Если сертификат выдан доверенным центром,
проверку лучше включить.

Параметры подключения меняются без удаления записи: меню записи (⋮) →
«Перенастроить». Запись обновляется только после успешной проверки, устройство и
сущности сохраняются; отвечать должен тот же NAS — для второго нужна отдельная
запись.

Для Home Assistant стоит завести отдельного пользователя ADM: пароль хранится в
записи интеграции, потому что без него нельзя восстановить истёкшую сессию.

## Сущности

- **Сенсоры**: загрузка процессора и ядер, нагрузка за 1/5/15 минут, память в
  МиБ и процентах, температура процессора, кулеры, время работы, приём и
  передача по активным интерфейсам, объём и заполнение томов, температура и
  ввод-вывод дисков, сессии, обновления App Central, внешние диски.
- **Двоичные сенсоры**: проблема тома, проблема диска, девять сервисов (SMB,
  NFS, FTP, WebDAV, SSH, SFTP, rsync, SNMP, TFTP), доступность обновления ADM,
  наличие и готовность внешних дисков.
- **Кнопки**: выключение, перезагрузка, сон — если модель поддерживает.
- **Обновление**: прошивка ADM, только при подтверждённой более новой версии.

Атрибуты SMART публикуются у отключённой по умолчанию сущности «SMART» и
обновляются по требованию через `homeassistant.update_entity`. Нулевое чтение с
диска при активной передаче — следствие кэша страниц NAS, а не неисправность.

### Обновления ADM

Признак обновления строится только на сверке версий: включён, когда ADM сообщает
целевую версию строго новее установленной. Флаг уведомления ADM на состояние не
влияет — на проверенной прошивке он остаётся включённым и при последней версии;
вместе со временем проверки он публикуется как атрибут сенсора. ADM 5.1.4
целевую версию не сообщает, поэтому сенсор там остаётся «недоступно» — это
ожидаемо. Установка обновления из Home Assistant не поддерживается.

## Интервалы опроса

- быстрый — 60 секунд: ресурсы, тома, диски;
- медленный — 300 секунд: сервисы, сессии, обновления, RAID, внешние диски.

Оба интервала меняются в настройках записи без перезапуска. Опрос не даёт дискам
NAS засыпать: если это важно, интервалы стоит увеличить.

## Управление питанием

> **Внимание.** Выключение и перезагрузка прерывают работу всех служб NAS,
> включая активные записи и передачи данных.

Команда отправляется только по явному действию пользователя. После неё сущности
становятся недоступными до первого успешного ответа, повторных отправок
интеграция не делает. Выключение из интерфейса ADM или кнопкой на корпусе
выглядит так же.

## Ограничения

- Двухфакторная авторизация ADM не поддерживается: настройка завершится явной
  ошибкой.
- Проверено на ADM 5.x и одном устройстве; набор фикстур расширяется по отчётам
  о других моделях.
- Одна запись интеграции — один NAS.
- UPS не поддерживается: API ADM отдаёт только конфигурацию, без состояния
  батареи.
- Иконка и логотип — товарный знак ASUSTOR из каталога `dashboard-icons`,
  используются только для идентификации устройства.

## Демо-стенд ASUSTOR

Контракт API можно проверять на открытом демонстрационном портале ASUSTOR.

| Что | Значение |
|---|---|
| Веб-интерфейс | <https://asrdemo.myasustor.com:8481/portal/> |
| API | `https://asrdemo.myasustor.com:8481/portal/apis` |
| Учётная запись | `demo-ru` / `demodemo` — публичная, права администратора |
| Устройство | AS7110T, ADM 5.1.4.DM62: 10 отсеков, 4 порта, 2 кулера, 2 тома, 4 диска |

Стенд подтверждает формы ответов и обязательные параметры запросов, но не
значения метрик: другая модель и сборка (`DM62` вместо `RM62`), сессия удалённая,
2FA выключена, внешних дисков и задач нет. Стенд общий — не меняйте на нём
настройки и не отправляйте команды питания. Ответы со стенда попадают в фикстуры
только после санитизации ([правила](tests/fixtures/README.md)).

## Диагностика

Выгрузка содержит версию ADM, состояния сервисов и ошибки опроса. Пароль,
идентификатор сессии, серийный номер и адреса маскируются.

## Версии и релизы

Версия — файл `VERSION` (единственный источник); `manifest.json` и
`pyproject.toml` к нему приводит `scripts/bump_version.py`.

Выпуск запускается сам: как только в `main` попадает `VERSION` с большим
номером, workflow `Release` ставит тег `vX.Y.Z` и публикует релиз. Повторный
пуш с уже выпущенной версией ничего не создаёт, а уменьшение номера — ошибка.
Ручной запуск (Actions → Release → Run workflow) остаётся, когда номер поднимает
сам workflow: `level` (`patch`, `minor`, `major`), `version` или `current` —
опубликовать уже подготовленную версию; `dry_run` показывает план.

К релизу прикладываются:

- список изменений относительно прошлого релиза — раздел `CHANGELOG.md`
  выпускаемой версии, коммиты с прошлого тега (сгруппированы по Conventional
  Commits) и ссылка сравнения;
- архив `asustor_adm-X.Y.Z.zip`, внутри — `custom_components/asustor_adm/`.
  Распаковка в корень конфигурации Home Assistant даёт готовый плагин без HACS:

  ```bash
  unzip asustor_adm-0.2.0.zip -d /config
  ```

  После распаковки перезапустите Home Assistant. Установка через HACS
  продолжает работать как раньше — HACS берёт исходники тега.

Изменения описываются в разделе `## [Unreleased]` файла
[CHANGELOG.md](CHANGELOG.md): при выпуске раздел становится разделом версии.
Релиз собирается атомарно — черновик, архив, публикация, — поэтому релиз без
архива не появляется: сбой загрузки оставляет черновик, и следующий запуск
доводит его до конца.

## Создано с использованием LLM

Код, тесты и документация подготовлены с помощью большой языковой модели под
контролем автора. Поведение зафиксировано в спецификациях OpenSpec и проверено
автотестами (305 сценариев на санитизированных ответах). Сгенерированный код
может содержать ошибки: проверьте его перед использованием на важных данных.
