# ASUSTOR NAS (ADM) для Home Assistant

Кастомная интеграция Home Assistant для NAS ASUSTOR под управлением ADM.
Работает через внутренний HTTP API ADM на порту 8001 — без SNMP и без облака
ASUSTOR: мониторинг ресурсов, здоровье дисков и RAID, статусы сервисов,
доступность обновлений и управление питанием.

Домен интеграции — `asustor_adm`, репозиторий — `ha-asustor-adm`.

## Требования

- NAS ASUSTOR с ADM 5.x (проверено на AS3304T, ADM 5.1.4.RM62) и включённой
  службой ADM на порту 8001.
- Home Assistant 2025.1 или новее.
- Учётная запись ADM. Для кнопок выключения и перезагрузки нужны права
  администратора.

## Установка через HACS

1. HACS → Интеграции → меню → «Пользовательские репозитории».
2. Добавить `https://github.com/SofroN/ha-asustor-adm`, категория «Integration».
3. Установить интеграцию и перезапустить Home Assistant.
4. Настройки → Устройства и службы → «Добавить интеграцию» → «ASUSTOR NAS (ADM)».

## Версии и релизы

Номер версии хранится в файле `VERSION` в корне репозитория — это единственный
источник истины. Из него версию получают `custom_components/asustor_adm/manifest.json`
(его читает HACS) и `pyproject.toml`; равенство трёх значений проверяет тест,
поэтому номер в этих файлах не правится вручную.

Выпуск — Actions → Release → Run workflow:

| Вход | Назначение |
|---|---|
| `level` | `current` — выпустить текущую версию из `VERSION`; `patch`, `minor`, `major` — поднять номер |
| `version` | явная версия `X.Y.Z`, приоритетнее `level`; оставить пустым, если не нужна |
| `dry_run` | показать, что будет выпущено, ничего не меняя |

Workflow обновляет `VERSION`, манифест, `pyproject.toml` и `CHANGELOG.md`, ставит
тег `vX.Y.Z` и публикует релиз на том хостинге, где запущен. Изменения описываются
в разделе `## [Unreleased]` файла [CHANGELOG.md](CHANGELOG.md): при выпуске он
превращается в раздел версии, а его текст становится описанием релиза — пустой
раздел выпустить нельзя.

HACS устанавливает код из тега релиза, поэтому версия в манифесте обязана совпадать
с тегом: это гарантирует `scripts/bump_version.py`, а не ручная правка.

## Настройка

| Поле | Значение по умолчанию | Комментарий |
|---|---|---|
| Адрес | — | имя хоста или IP-адрес NAS |
| Порт | 8001 | порт службы ADM |
| Использовать HTTPS | включено | штатный режим ADM |
| Проверять TLS-сертификат | включено | отключается для самоподписанного сертификата |
| Учётная запись | — | имя пользователя ADM |
| Пароль | — | пароль ADM |

### Самоподписанный сертификат

ADM по умолчанию использует самоподписанный сертификат, который Home Assistant
не может проверить. В этом случае при настройке отключите «Проверять
TLS-сертификат»: соединение останется шифрованным, но подлинность сертификата
не проверяется. Включайте проверку, если NAS использует сертификат от
доверенного центра.

### Отдельная учётная запись

Рекомендуется завести отдельного пользователя ADM для Home Assistant: пароль
хранится в записи интеграции, потому что сессия ADM живёт ограниченное время
(`timeout_minutes: 60`) и без пароля восстановить её невозможно. Для учётной
записи без прав администратора интеграция не создаёт кнопки питания.

## Сущности

- **Сенсоры**: загрузка процессора и каждого ядра, средняя нагрузка за 1/5/15
  минут, использованная память в МиБ и в процентах, температура процессора,
  обороты кулеров, время работы, приём и передача по каждому активному
  сетевому интерфейсу, объём и заполнение томов, температура, чтение и запись
  по каждому диску, активные сессии, обновления App Central, внешние диски.
- **Двоичные сенсоры**: проблема тома, проблема диска, включение девяти
  сервисов (SMB, NFS, FTP, WebDAV, SSH, SFTP, rsync, SNMP, TFTP), доступность
  обновления ADM, наличие и готовность внешних дисков.
- **Кнопки**: выключение, перезагрузка, сон (если модель поддерживает).
- **Обновление**: сущность прошивки ADM создаётся только при подтверждённой
  целевой версии.

Атрибуты SMART диска (переназначенные секторы, секторы, ожидающие
переназначения, температура, наработка в часах) запрашиваются по требованию
через `homeassistant.update_entity` для отключённой по умолчанию сущности
«SMART»: в регулярном цикле опроса этот запрос не выполняется.

## Интервалы опроса

Интеграция использует два независимых цикла:

- быстрый, по умолчанию 60 секунд — ресурсы, тома, диски;
- медленный, по умолчанию 300 секунд — сервисы, сессии, обновления, RAID,
  внешние диски.

Интервалы меняются в настройках записи и применяются без перезапуска Home
Assistant. Каждый опрос обращается к NAS, поэтому диски NAS могут не засыпать:
если это важно, увеличьте оба интервала.

## Показатели чтения и кэш страниц

Показатель чтения с диска зависит от кэша страниц NAS. Если запрошенный файл
уже находится в кэше (на AS3304T это около 1 ГиБ из 1.9 ГиБ памяти), счётчик
чтения диска остаётся нулевым, хотя файл активно передаётся клиенту. Нулевое
чтение при активном обращении не является неисправностью диска или интеграции;
в этот момент растёт показатель передачи по сети.

## Управление питанием

> **Внимание.** Выключение и перезагрузка прерывают работу всех служб NAS,
> включая активные записи и передачи данных. Команда отправляется только по
> явному действию пользователя: из интерфейса, автоматизации или сценария.

После успешной команды сущности становятся недоступными и остаются такими,
пока NAS снова не ответит; повторных отправок команды интеграция не делает.
Выключение из интерфейса ADM или кнопкой на корпусе выглядит так же —
недоступностью сущностей, а не сбоем интеграции.

## Ограничения

- Двухфакторная авторизация ADM пока не поддерживается: при включённой 2FA
  настройка завершится явной ошибкой.
- Проверка проведена только на ADM 5.x и одном устройстве; набор тестовых
  ответов расширяется по отчётам о других моделях.
- Одна запись интеграции — один NAS.
- UPS не поддерживается: API ADM отдаёт только конфигурацию, без состояния
  батареи.

## Тесты

Быстрый набор не требует Home Assistant (106 тестов: клиент API, разбор ответов,
преобразование значений, манифест, переводы и версия):

```bash
pip install pytest pytest-asyncio pytest-aiohttp aiohttp
python -m pytest tests/unit -q --confcutdir=tests/unit
```

Полный набор (200 тестов: config flow, сущности, координаторы, диагностика)
запускается с установленным Home Assistant:

```bash
pip install -r requirements_test.txt
python -m pytest -q
```

В CI на каждый пуш выполняются линт и быстрый набор; полный набор запускается
вручную: Actions → CI → Run workflow → `full_suite`.

## Диагностика

Выгрузка диагностики содержит версию ADM, состояние сервисов и ошибки
координаторов. Пароль, идентификатор сессии, паспорт учётной записи, серийный
номер и адреса маскируются; query string запросов в диагностику не попадает.

## Создано с использованием LLM

Код интеграции, тесты, фикстуры и эта документация подготовлены с использованием
большой языковой модели (LLM) под контролем автора. Контракт ADM API восстановлен
по захватам реальных запросов к NAS, поведение зафиксировано в спецификациях
OpenSpec и проверено автотестами (200 сценариев на санитизированных ответах).
Сгенерированный код может содержать ошибки: перед использованием на важных данных
проверьте его самостоятельно, а ответственность за поведение интеграции на вашем
NAS остаётся за автором репозитория.
